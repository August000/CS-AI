QS1.1:
In computeActionFromValues, I initally get all the legal actions for the given state using
self.mdp.getPossibleActions(state). If there are no legal actions (like at a terminal state),
I return None. Otherwise, I loop through all the actions and find the one that gives the
highest Q-value by calling computeQValueFromValues for each action. I used Python's max()
function with a key that computes the Q-value for each action, so it returns the action
with the best expected value. This is basically implementing the policy: pick the action
that maximizes the expected utility from the current state.

QS1.2:
For computeQValueFromValues, I compute Q(s, a) using the Bellman equation. I go through
all the possible next states and their transition probabilities by calling
self.mdp.getTransitionStatesAndProbs(state, action). For each (nextState, prob) pair, I get
the reward R(s, a, s') and then calculate prob * (reward + discount * V(s')), where V(s')
is the value of the next state stored in self.values. I sum all of these up to get the
final Q-value. So basically each transition contributes its probability times the immediate
reward plus the discounted future value.

QS3.1:
For 3a (close exit, risk cliff), I used discount=0.2, noise=0.0, livingReward=0.0. The low
discount means the agent doesn't care much about rewards far in the future, so the close
+1 exit looks better than the distant +10. For example, with discount=0.2, the +10 exit
that's 5 steps away is only worth about 0.2^5 * 10 = 0.00032 at the start, while +1
that's 3 steps away is worth 0.2^3 * 1 = 0.008, which is way more. Noise=0 means there's
no chance of slipping into the cliff, so walking along the bottom row is safe.

For 3b (close exit, avoid cliff), I used discount=0.3, noise=0.2, livingReward=-0.5. The
noise=0.2 makes the cliff dangerous because there's a 10% chance of slipping sideways
into the -10 states when walking along the bottom row. The negative living reward pushes
the agent to reach an exit quickly rather than wandering, and the low discount still makes
the close +1 exit more attractive than the far +10. So the agent takes the safe path
around the top to reach +1.

For 3c (distant exit, risk cliff), I used discount=0.9, noise=0.0, livingReward=0.0. The
high discount means future rewards keep most of their value, so +10 far away is still
worth a lot more than +1 nearby. With noise=0, walking along the bottom row next to the
cliff is perfectly safe, so the agent just goes straight east along the bottom to reach +10.

For 3d (distant exit, avoid cliff), I used discount=0.9, noise=0.2, livingReward=0.0. The
high discount still makes the +10 exit more desirable than +1. But now noise=0.2 makes the
cliff risky, so the agent goes north and takes the long safe path around the top of the
grid to get to +10 without risking the -10 cliff.

For 3e (avoid all exits), I used discount=0.9, noise=0.2, livingReward=11.0. With a living
reward of +11 per step, the agent earns more by just staying alive than it would by exiting.
Even the +10 exit can't compete with collecting +11 every single step, so the agent avoids
all terminal states and just keeps moving around forever.

QS5.1: explain how you implemented your Q-learning agent.

First I updated the init function to set the self.qvalues to an empty Counter(). This is like a dictionary but returns 0.0 for unseen pairs. 
The getQValue function was also very simple. I simply return the q values at the given state action pair using "self.qValues[(state, action)]". 
Next I implemented the computeValueFromQValues() function by looping through the legal actions(returning 0.0 if there are no legal actions), checking the q value for each state/action pair, and returning the maximum one. This is necessary for our observed q value calculation. 
The computeActionFromQValues() function was similar in that it loops through the actions to find the best one, but instead of returning the best value, it tracks the best action(s)(stores multiple actions in a list if there are ties). Then, it returns one of the best actions(or the best action if only one) by randomly selecting between them using random.choice(). 
Finally, we implemented the update() function, which is core to the Q learning algorithm. To do this, we pulled the current q value at the given state and found the max q value of the next state relative to action by calling computeValueFromQValues(nextState). We then calculated our observed q value by adding the reward to the discounted q value of the next state(which we just found). We then found the error between the observed and current q values by finding the difference. Then, we have everything we need for the final update rule. We add the current q value and the error(weighted by alpha) together to get our updated q value, which we store in self.qValues[(state, action)]. 
This all together allows our Q-learning agent to store and update its q values over time.

QS6.1: You can also observe the following simulations for different epsilon values. Does that behavior of the agent match what you expect? Explain. 

Yes, the observed behavior did match my expectations.
For the low epsilon(epsilon=0.1), we would expect less random exploration and more path following based on policy. In our test run, we saw just that. The agent took a handful of iterations to find a successful path to the reward state, but once it found one it quickly started following almost that exact path repeatedly with only little variance. After reaching the goal state several times the pattern got even stronger. This resulted in the agent repeatedly finding the goal state and finding the converged q values on its found path, but ignoring other potential paths to the goals almost entirely. This meant that some of the states weren't visited much and therefore weren't ever able to reach a solid converted q value.
By contrast, for the higher epsilon(epsilon=0.9), we would expect more random exploration. This is exactly what we saw. The agent never completely settled on a path and therefore fully explored all states, resulting in finding converges q values for all of them. This of course meant that it also wasn't reaching the goal state as often or as efficiently.
These results go to show us the value in altering the epsilon value for different use cases. For example, low epsilon may be more useful if you want to find any goal path and build confidence in it quickly, or in cases where excess exploration or reaching failure states is costly. Whereas high epsilon may be preferable in cases where you want to explore all states as much as possible to fully flesh out your q values for any situation.
